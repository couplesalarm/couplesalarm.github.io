# Legacy Android beta applications

The current page at `/beta/android/#application` directs people to join the existing Google Group and then opt in on Google Play. It has no website email form and does not call this endpoint. Both access links are available immediately, without JavaScript or a saved application.

This endpoint remains available for cached older forms and preserves earlier applications. Those forms ask only for the Google Play email and save with the project's public anon JWT. Gateway JWT verification stays enabled; the handler checks the site origin and email. It never accepts applicant reads or tester admission requests. A valid public JWT is not compared byte-for-byte with the runtime's generated anon token, which can represent the same project with different token timestamps.

Signups are stored in `public.couples_alarm_android_beta_applications` in the existing Couples Alarm project `xqdqgsbkapvlskcldmpe`, database `postgres`, host `db.xqdqgsbkapvlskcldmpe.supabase.co`. RLS is enabled with no public policies; `anon` and `authenticated` have no table privileges. Server-only credentials write the validated email and signup-notice version. No applicant information is included in a response or logged.

Email-only submissions from cached forms use source `website_android_beta_email_v2` and notice version `android_beta_email_notice_v2`. Submitting those forms requests beta contact and access as disclosed beside the button; there is no consent checkbox. Device, age, explicit consent-checkbox and 14-day-commitment columns stay null. Extra fields from cached older forms are ignored. Do not treat these null fields as failed signup requirements or as confirmed age/commitment. Existing older applications and their original answers are preserved; duplicate emails do not overwrite them.

The existing Supabase project owner can review applications in the project's Table Editor, ordered by `created_at, id`. Duplicate normalized emails retain the original application and consent. This endpoint does not send emails, select or invite testers, add Google Group members, or create purchases. The current self-service path is to join `https://groups.google.com/g/couples-alarm-android-beta/about`, then opt in at `https://play.google.com/apps/testing/com.couplesalarm.android` with the same Google account. The group currently allows anyone on the web to join without organizer approval, and it is selected on the published Closed Alpha track. No saved website application, organizer action, or confirmation email is required for this path. Google records membership and opt-in through its existing services. The previous Google Form and its responses are untouched.

The prepared Google Forms admission worker has not been activated and does not read this new source. Use the private table for website applications; do not assume that worker processes them. The user's Google Group join and Google Play opt-in are separate from saving their email. The live track and group settings were read back on October 8, 2026 UTC; recheck them before making future availability claims.
